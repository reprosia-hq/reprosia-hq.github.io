The open-source tooling.

Reprosia does not replace your analysis environment or your validation process. It adds the records they need to stand up to review, including when an AI assistant was involved.

Where it sits.

The packages are ordinary R packages, so they fit wherever you already run R.

Your R environment

  • Analysis scripts and packages
  • RStudio or Posit Workbench
  • Git and CI
  • The AI assistant you choose

Evidence layer

  • regulog records actions in a tamper-evident log
  • lineager traces rows and exclusions
  • reproducr locks and checks the environment

What QA and reviewers receive

  • Audit log extracts that can be verified
  • Provenance reports
  • Qualification scripts and results
  • Reproducibility checks and drift reports

Audited AI assist In development

The next layer captures the AI step itself. The design below is a sketch of the intended workflow, not released software.

  1. Scope the task

    Write down the context of use: what the assistant may do and what it may not.

  2. Capture the draft

    Log the prompt, the model and its version, and the output it returned.

  3. Record the review

    A named reviewer accepts, edits or rejects the output. The decision joins the same chain.

  4. Fix the data

    Hash the input datasets and exclusions so the run points at an exact data version.

  5. Replay

    Re-run in the locked environment and compare outputs to the logged result.

Design sketch. Function names are illustrative and the API is not final.

# Not released. Illustrates the intended shape.
session <- ai_session(
  task  = "Derive change from baseline for ADLB",
  data  = adlb,
  log   = regulog_path
)
draft  <- ai_draft(session, model = my_model)
review <- ai_review(draft, reviewer = "jsmith",
                    decision = "accept")
ai_replay(session)  # locked environment, recorded seed

What it is not.

Stating the limits plainly is part of the product.

Not a validated system out of the box
Your own computer system validation still applies. regulog ships qualification scripts to support it, and the results belong to your installation.
Not a compliance certificate
The software is designed around 21 CFR Part 11 and EU Annex 11. Whether a deployment is compliant depends on how it is configured, governed and validated.
Not submission assembly
Reprosia does not build eCTD packages or generate Define-XML. lineager produces provenance reports that can support a Reviewer's Guide.
Not an AI model
It records and verifies what happened around a model you select. It does not judge whether the model is right.

Four questions an auditor will ask.

Four questions come up whenever an auditor looks at AI-assisted analysis. Each one maps to something that exists today or something being built.

  • What did the AI touch?

    regulog writes each action to a hash-chained, user-attributed log, so a missing or altered entry shows up on verification. Capturing prompts and model output in that same log is in development.

    regulog on CRAN
    AI capture in development

  • Which data was it run on?

    lineager traces rows from source to analysis dataset, records every exclusion with its reason, and writes a provenance report styled after the CDISC Reviewer's Guide.

    lineager on CRAN

  • Who reviewed it, and what did they decide?

    Most AI workflows keep no record of who accepted, edited or rejected an output. This is the first thing Reprosia is adding on top of regulog.

    In development

  • Can someone re-run it and get the same result?

    reproducr captures the session, locks dependencies, certifies scripts and flags drift when results change.

    reproducr on CRAN
